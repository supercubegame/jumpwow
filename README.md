# JUMPWOW

无限向上跳跃。踩着平台一路往上，掉出屏幕就结束。

纯 Node.js，**零运行时依赖**,不用 `npm install`，clone 下来直接跑。

```bash
git clone https://github.com/supercubegame/jumpwow.git
cd jumpwow
npm start
```

## 玩

| 键 | 作用 |
| --- | --- |
| `A` / `←` | 向左 |
| `D` / `→` | 向右 |
| `S` / 空格 | 停住 |
| `Q` | 退出 |

落地自动起跳，不用按跳。世界左右相通,从右边走出去会从左边回来，
这经常是躲开一段烂路的最快解。

```bash
npm start -- --seed 42      # 指定地图，同一个种子永远是同一张图
npm start -- --bot          # 看机器人玩
npm start -- --bench 60     # 无头跑 60 秒，打印统计
```

## 平台

| 样子 | 类型 | 行为 |
| --- | --- | --- |
| `======` | 普通 | 正常弹跳 |
| `~~~~~~` | 移动 | 左右摆动 |
| `------` | 易碎 | 弹一次就碎 |
| `^^^^^^` | 弹簧 | 跳到 2.6 倍高 |

难度随高度爬升：间距变大，移动和易碎平台变多，400 高度后打满。

## 验证闸门

```bash
npm run verify
```

一条命令回答一个问题：**这份代码现在还能不能玩？** 通过返回 0，失败返回 1。

12 项断言里最有价值的是第 7 项：让无头机器人在 24 个随机种子上各玩满 60 秒。
单元测试能证明函数返回值对，但证明不了关卡生成了一段跳不上去的死路。
机器人连续几百次跳跃不死，才说明物理参数和生成参数是自洽的。

其余覆盖：确定性（同种子必须完全复现）、种子差异性、可达性不变量、
无 NaN、无坐标越界、平台数组有界（不泄漏）、高速下落不穿板、
难度曲线单调、性能预算、CLI 退出码。

每次 push 由 GitHub Actions 自动跑，结果回写到 PR 评论。

```bash
SEEDS=40 SURVIVE_SEC=90 npm run verify    # 想加严
```

## 结构

```
src/engine.js        纯引擎，不碰任何 I/O，同种子必然同结果
src/bot.js           无头机器人
src/render.js        终端渲染
bin/jumpwow.js       CLI 入口
test/engine.test.js  单元测试
scripts/verify.mjs   验证闸门
```

`src/engine.js` 里没有一行涉及终端或文件系统。它是可以整个搬到浏览器里
配一个 canvas 渲染器就能跑的,这也是它容易测的原因。
