# JUMPWOW

无限向上跳跃。踩着平台一路往上，掉出屏幕就结束。

**在线试玩 → https://supercubegame.github.io/jumpwow/**

手机也能玩，点屏幕左右半边。

**零运行时依赖。** clone 下来直接跑，终端和浏览器都能玩。

```bash
git clone https://github.com/supercubegame/jumpwow.git
cd jumpwow

npm start        # 终端里玩
npm run serve    # 起服务，浏览器打开 http://localhost:8000/web/index.html
```

浏览器版有排行榜和分享卡片，终端版更轻。两边跑的是同一份引擎。

## 玩

| 输入 | 作用 |
| --- | --- |
| `A` `D` 或方向键 | 左右移动 |
| 手机 | 点屏幕左右半边 |
| `Q`（终端） | 退出 |

落地自动起跳，不用按跳。世界左右相通,从右边走出去会从左边回来，
这经常是躲开一段烂路的最快解。

| 样子 | 平台 | 行为 |
| --- | --- | --- |
| 绿 `======` | 普通 | 正常弹跳 |
| 蓝 `~~~~~~` | 移动 | 左右摆动 |
| 黄 `------` | 易碎 | 弹一次就碎 |
| 粉 `^^^^^^` | 弹簧 | 跳到 1.6 倍高 |

难度随高度爬升，400 高度后打满。

## 排行榜：改分数没用

客户端**不上报分数**。它上报的是「种子 + 每一帧按了什么」，
服务端拿同一份引擎重放一遍，以**重放算出来的分数**为准。

改内存、改请求体里的 score 字段，全都没有意义,服务端根本不看它。
想上榜只有一个办法：真的玩到那个高度。

这不是特意加的反作弊系统，而是「引擎必须是确定性纯函数」这条约束的
免费副产品。同一个种子加同一串输入必然产出同一个结果，那么一局游戏
本身就是自证明的。

提交的日志用游程编码，一局 60 秒通常只有几百字节。

分享卡片会把种子印在上面,别人打开同一个种子就是同一张图，可以真比。

> 在线版部署在 GitHub Pages 上，纯静态，没有服务端。所以那里的排行榜
> 会自动降级成**本机榜**（存在你自己浏览器里），界面上标了「仅本机」。
> 想要带重放验证的全球榜，本地 `npm run serve` 或自己部署一份。

## 验证闸门

```bash
npm run verify        # 引擎，17 项，零依赖，约 20 秒
npm run verify:web    # 浏览器，13 项，要装 playwright，约 1 分半
```

拆成两个是因为快闸门的价值在于快。绝大多数改动不碰渲染层。

**引擎闸门 17 项**里最有价值的是第 7 项：让无头机器人在 24 个随机种子上
各玩满 60 秒。单元测试能证明函数返回值对，但证明不了关卡生成器造出了
一段跳不上去的死路。机器人连续几百次跳跃不死，才说明物理参数和生成
参数是自洽的。

第 14-17 项守着排行榜的根基：重放必须与实跑逐字段一致、改一个字节分数就
对不上、服务端以重放值判分并拒绝伪造。**哪天有人往引擎里塞了 `Date.now()`，
第 14 项会立刻红**,而不是等到线上被刷榜才发现。

其余覆盖：确定性、种子差异性、可达性不变量、无 NaN、无坐标越界、
平台数组有界、高速下落不穿板、难度曲线单调、性能预算、CLI 退出码。

**浏览器闸门 13 项**：模块加载、画面非空白、**游戏画面采样颜色数多于菜单**
（证明平台真的画出来了，不是一块纯色）、输入被记入日志、分享卡片有真实
像素、机器人在浏览器里存活、**API 挂掉时游戏照常能玩**。

每次 push 由 GitHub Actions 跑，结果回写到 PR 评论。

## 结构

```
src/engine.js        纯引擎，不碰任何 I/O，同种子必然同结果
src/replay.js        输入日志编解码 + 重放，同样是纯函数
src/bot.js           无头机器人
src/render.js        终端渲染
web/index.html       canvas 渲染器 + 排行榜前端
server/api.mjs       排行榜 API，零依赖
bin/jumpwow.js       CLI 入口
scripts/verify*.mjs  两道闸门
```

`src/engine.js` 里没有一行涉及终端、文件系统或 DOM。所以它能同时被
终端渲染器、浏览器 canvas 和服务端重放复用,加浏览器版的时候，
引擎一行都没改。
